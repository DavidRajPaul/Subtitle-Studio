## What now works (Phase 1)

- **Home** with the two workflow entry points: "Transcribe speech" and "Create subtitles from text".
- **Import screen** (workflow preselected, switchable without losing the video): MP4 picker, inspecting state with Cancel, metadata (duration, resolution + portrait flag, frame rate, audio track, size), Replace and Remove.
- **Validation beside the field** with a next action: wrong extension and empty file (checked in the browser before sending), unreadable/fake MP4, non-MP4 container, audio-only MP4, unreadable duration, missing FFprobe, backend not running.
- **Speech workflow + silent video:** explains there is no speech and offers "Use a text file instead".
- **Preview:** plays the user's file from the device; Play/Pause, current/total time, scrubber, and a numeric "Go to time" field (HH:MM:SS.mmm, MM:SS or seconds) with validation. Playback-format errors are explained.
- **Backend:** `POST /api/media` copies the upload into an app-owned folder (`data/media/<uuid>.mp4`, gitignored), probes it with FFprobe (argument array, 30 s timeout), returns integer-millisecond metadata, and deletes partial/failed copies. `DELETE /api/media/{id}` removes a working copy; IDs must be UUIDs (no path traversal). The original file is never modified.
- Settings → Diagnostics (Phase 0 health panel) remains available.

## Decisions made (reversible)

1. **Working copy:** the backend copies the chosen MP4 into `data/media/` so later phases can run FFmpeg on it; this doubles disk use for each imported video. Preview plays the original from the browser, not the copy.
2. **MP4 detection** uses FFprobe's container family (`mov,mp4,…`) plus the `.mp4` extension; cover-art images are not counted as video.
3. **No upload size limit yet** (local-only). Revisit in Phase 6.
4. **No router library:** three views are held in React state.

## Known limitations and unresolved decisions

- **Orphaned working copies:** if the browser or backend closes while a video is loaded, its copy stays in `data/media/`. Safe cleanup belongs with project save/load (Phase 3) and hardening (Phase 6), so copies referenced by saved projects aren't deleted.
- Optional MP3 picker is Phase 4; TXT import is Phase 2. The import screen says so instead of showing dead controls.
